# fish_stock_forecast

Веб-приложение для оценки запасов рыб озера Жайсан, прогноза на 5 лет и расчёта ПДУ.
Исходные данные берутся из соседнего проекта `fish_stock_assesment_1` (папка `data_catch`);
его файлы не копируются и не изменяются.

Возраст j в данных (`less_j`) — рыбы в возрасте от j−1 до j лет. В интерфейсе он подписан как
«1–2», «2–3» и т. д.: j = 2 — возраст 1–2 года (двухлетки), j = 1 — сеголетки (в уловах их нет).

## Что готово

### Этап 1. Уловистость невода — страница «Уловистость невода»
Сигмоида по возрастным группам, параметры находятся методом наименьших квадратов по годовым уловам
(формулы (24)–(26) статьи):

```
c_j = b / (1 + exp(-a (j - j50))),            j = 2 … m1
ln Y_j = K - Z j + ln σ_j                      (кривая улова: Y_j ≈ c_j · N0 · exp(-Z j))
min Σ w_j (ln Y_j - K + Z j - ln σ_j)²          по a, j50, Z, K;  w_j — число рыб в пробе (+1)
(1/(m1-1)) Σ c_j = c̄                            условие (25); b — из него
c_j <= 0.8;  c_j >= 0.1 начиная с возраста 2–3;  для возраста 1–2 (двухлетки) c >= 0.01     (26)
```

### Этап 2. Запас по уловам — страницы «Запас по уловам» и «Уловистость сети»
- **Улов по каждому лову** и возрастной группе: улов лова × доли возрастной пробы года (как save_catch_3d).
- **Уловистость сети** — парабола (22)–(24) статьи: вершина c¹ = max(m0+1, группа наибольшего улова),
  a1 = (c̄−0.1)/(2−c¹)², a2 = (c̄−0.2)/(m1−c¹)², c⁰ из условия среднего (23).
- **Модель баланса** 12 колец (перенос calc_model_for_net без изменений; таблица 9 статьи
  воспроизводится при V = 72 м/ч).
- **Запас по лову:** сеть — как в старом коде `X = Y·S / (σ·(V² − r0²))` (формула (28) статьи
  `X = Y·S / (π V² σ)` включается настройкой `NET_STOCK_FORMULA` в `core/config.py`);
  невод — формула (27) `X = Y·S / (c·s_area)`.
- **Годовой запас:** «по запасам» (среднее оценок по ловам) и «по годовому улову»
  (невод: ΣY / Σs_area; сеть: средний улов на лов) — отдельно для сети и невода.
  Окончательный запас по каждому возрасту — средневзвешенное сети и невода по числу ловов
  (`COMBINE_GEARS` в `core/config.py`); суммарный запас — сумма окончательных запасов по возрастам.
- Варианты уловистости: «по возрастам» и «средняя по виду» (одна c̄ на вид).
- Ловы, где вид не учитывался (пропуск в исходной таблице), исключаются; нулевые уловы учитываются.

Результаты сохраняются в `results/` под теми же именами, что в `data_stock` исходного проекта
(`zhaysan_catch_net_3d.nc`, `zhaysan_stock_seine_with_ages_3d.nc`,
`zhaysan_yearly_stock_net_with_ages_on_stock_3d.nc` и т. д.), плюс окончательный запас
(`zhaysan_yearly_stock_combined_*`).

### Этап 3. ПДУ по возрастам — страница «ПДУ по возрастам»
Официальный ПДУ НПЦ (т) переводится в штуки по возрастам (раздел 5 статьи): квота делится между
половозрелыми возрастами пропорционально биомассе окончательного запаса с нагрузкой j/m1; за итерацию из
возраста изымается не больше 75 % остатка; итерации идут, пока квота не исчерпана или не закончится
свободный запас. Средний вес недостающих возрастов (язь, 12–13) берётся от ближайшего младшего.
Результат: `results/zhaysan_pdu_pieces_3d.nc` (год × вид × возраст) — вход байесовской модели.

### Этап 4. Байесовская модель — страница «Байесовская модель»
Когортная модель одного вида по уравнениям (16)–(17) статьи (PyMC, NUTS). Восемь старых скриптов
`calc_stock_bayes_2g1p_*.py` заменены одной моделью, которая собирается по настройкам вида
(`core/bayes/config.py`): значения по умолчанию — из последних версий скриптов (lesh8, sudak4, okun5,
plotva4, shuka6, sazan5, karas28, yaz5), включая варианты формул (вычитание вылова `tanh` / `maximum` /
`softplus`, граница хищников, обрезка смертности и др.). Имена и порядок случайных величин те же.

- **Входные данные:** правдоподобие — оценки запаса по каждому лову сети и невода (этап 2, с учётом возрастов);
  вылов A_j(t) — ПДУ НПЦ в штуках по возрастам (этап 3); начальный запас первого года — окончательный
  годовой запас по возрастам (средневзвешенное сети и невода); сеголетки 0–1 первого года — от нерестового
  стада внутри модели, как в старом коде. Ловы, где вид не учитывался, по умолчанию исключаются
  (как на этапе 2; в старом коде считались нулевыми — переключается в настройках).
- **Настройки** редактируются на странице и сохраняются в `results/bayes_config.json` (только отличия
  от скрипта); кнопка «Вернуть значения скрипта» их сбрасывает.
- **Запуск** — в отдельном процессе (страницу можно закрыть), на странице видны этап, прогресс по цепям,
  оставшееся время, расходимости и журнал. Один вид — от 15 минут до 2 часов.
- **Априорная проверка** (секунды, без PyMC): 500 выборок из априорных распределений и динамика по ним —
  видно, накрывают ли полосы оценки по уловам, до долгого расчёта.
- **Сверка со старым скриптом:** входные данные старого проекта (`prepare_data_for_bayes` из скрипта вида),
  его настройки выборки и seed; результат сравнивается со старым `data_stock/zhaysan_bayes_2g1p_*.nc`.
- После выборки численность пересчитывается по тем же уравнениям на numpy и сравнивается с PyMC
  (строка «Сверка уравнений» в диагностике).

Результаты: `results/zhaysan_bayes_{вид}.nc` (те же переменные, что в старых .nc, плюс 95 % интервалы) и
`results/zhaysan_bayes_{вид}.npz` (сводки и 500 выборок параметров — для страницы и прогноза этапа 5).

### Этап 5. Прогноз и ПДУ — страница «Прогноз и ПДУ»
Прогноз на 1–10 лет (выбирается на странице) по 500 выборкам байесовской модели: каждая выборка
продолжается теми же уравнениями (16)–(17) от численности последнего года истории.

- **Площадь водоёма** задаётся на каждый прогнозный год (ёмкость нерестилищ K).
- **Естественная смертность** — по желанию на каждый год: доля половозрелых (j ≥ m0), погибающих за год
  (без хищников); форма кривой по возрастам — из модели. Пустая ячейка — «из истории»: кривая выборки
  со случайным годовым колебанием.
- **β** — среднее за 3 предыдущих года (с 4-го прогнозного года — по прогнозным годам).
- **γ, α** (хищники, множитель ёмкости) — случайный год истории той же выборки.
- Три сценария вылова (промысловые возрасты j ≥ m0):
  - **F = k·M по Баранову:** M_j = −ln((1 − s_j)/(1 + γ_j)), F = k·M̄ (средняя M промысловых возрастов,
    взвешенная по численности), C_j = F/(F + M_j)·(1 − e^(−(F+M_j)))·X_j; ПДУ года — по запасу на начало года;
  - **фиксированный ПДУ, т** (по умолчанию ПДУ НПЦ последнего года), распределённый по возрастам алгоритмом этапа 3;
  - **без промысла.**
- Результаты: численность, промысловая биомасса, ПДУ по годам (т и штуки по возрастам), вероятность
  снижения запаса, сводка по всем видам, Excel. Расчёт — numpy, около секунды на вид.

Настройки прогноза хранятся в `results/forecast_config.json`.

## Установка

```bat
cd D:\pythonprojects\fish_stock_forecast
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```
Для этапа 4 нужен PyMC (`pip install pymc`) — тот же, что в исходном проекте. Без него работают все
остальные страницы и априорная проверка.

## Запуск

Двойной щелчок по `run.bat`, затем http://127.0.0.1:8000.
Интерфейс работает без интернета (графики — собственный SVG-модуль).

Слева — меню по шагам расчёта (1 уловистость невода → 2 уловистость сети → 3 запас по уловам → 4 ПДУ по
возрастам → 5 байесовская модель → 6 прогноз и ПДУ) с отметками состояния; главная страница «Обзор» —
сводка по всем видам. Вверху каждой страницы — крупный выбор вида рыбы и года (стрелки ◀ ▶), он закреплён
при прокрутке; на каждой странице свой. Ссылка вида на «Обзоре» открывает страницу сразу с этим видом
(`?species=lesh`).

Сервер перезапускается сам только при изменении кода в `app\` и `core\` (`--reload-dir`), а не при
установке пакетов в `.venv` и не при записи файлов в `results\`.

Результаты этапов 1–3 запоминаются в `results\cache`: при следующем запуске сервер берёт их оттуда
за доли секунды. Пересчёт идёт, только если изменились исходные данные (`data_catch`), старые файлы
`data_stock` или код расчёта, либо по кнопке «Пересчитать». В окне сервера пишется время каждого этапа
и запросы дольше секунды — по ним видно, что тормозит.

Если исходный проект лежит не рядом: `set FISH_SOURCE_DIR=D:\путь\к\fish_stock_assesment_1`.

## Расчёты без веб-интерфейса

```bat
python -m scripts.calc_catchability_seine     & rem этап 1 + сравнение с прежними коэффициентами невода
python -m scripts.calc_stage2                 & rem этапы 2–3 + сверка с прежними файлами data_stock
python -m scripts.run_bayes --species окунь   & rem этап 4 для одного вида (15 мин – 2 ч)
python -m scripts.run_bayes --species все     & rem все 8 видов подряд — можно оставить на ночь
python -m scripts.run_bayes --species лещ --mode check   & rem сверка со старым скриптом
python -m scripts.run_bayes --species все --mode prior   & rem априорная проверка, секунды
```

## Структура

```
core/
  config.py               пути и настройки (границы уловистости, единицы площадей)
  data_source.py          чтение data_catch/*.py: свойства видов, уловы, пробы, данные НПЦ
  catchability_seine.py   этап 1: МНК-расчёт уловистости невода
  catch.py                улов по каждому лову и возрастной группе
  catchability_net.py     уловистость сети — парабола (22)–(24)
  net_model.py            модель баланса 12 колец, формула (28)
  stock.py                запас по ловам, годовой и окончательный запас (сеть+невод)
  pdu_npc.py              ПДУ НПЦ по возрастам (раздел 5 статьи)
  ages.py                 подписи возрастов «1–2», «2–3», …
  export_nc.py            запись .nc в формате старого проекта
  cache.py                кэш этапов 1–3 на диске, журнал времени расчёта
  forecast.py             этап 5: прогноз по выборкам модели, сценарии, ПДУ по Баранову
  bayes/
    config.py             настройки видов (значения скриптов) и их сохранение
    inputs.py             входные данные: этапы 2–3 или старый prepare_data_for_bayes
    dynamics.py           уравнения (16)-(17) — одни и те же для PyMC и numpy
    model.py              модель PyMC и выборка NUTS
    run.py                расчёт вида, сводки, R̂, запись .npz и .nc, априорная проверка
    jobfiles.py           состояние и журнал фонового расчёта
app/
  main.py                 FastAPI: страницы и API
  services.py             этап 1 для интерфейса
  services_stock.py       этапы 2–3 для интерфейса, выгрузки Excel
  services_bayes.py       этап 4 для интерфейса: настройки, результаты, Excel
  jobs.py                 фоновый процесс расчёта (запуск, состояние, остановка)
  services_forecast.py    этап 5 для интерфейса: настройки прогноза, сводка, Excel
  templates/, static/     HTML, стили, SVG-графики
scripts/                  расчёты из командной строки
tests/                    тесты
results/                  результаты расчётов
```
