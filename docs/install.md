## Требования и способы установки

### Состав

Приложение — семь сервисов на Python (FastAPI), воркеры расчётов, веб-интерфейс (Vue) и шлюз. Все данные хранятся в файлах в одном каталоге (томе) данных.

| Сервис | Порт без Docker | Назначение |
|---|---|---|
| users | 8001 | вход, пользователи, роли, журнал действий |
| data-model | 8002 | справочники, водоёмы, типы наборов данных |
| data-admin | 8003 | шаблоны, загрузка и версии исходных данных |
| algo-model | 8004 | моделирование алгоритмов |
| algo-admin | 8005 | каталог, профили, расчёты, очередь, результаты (и воркеры) |
| dashboards | 8006 | дашборды и мониторинг |
| help | 8007 | справка |
| шлюз | 8080 | единый адрес приложения: интерфейс и `/api/<сервис>/` |

### Требования

- **Сервер (рекомендуется)**: Linux (Ubuntu 22.04 или новее), Docker 24+ с Docker Compose; 4 ядра и 8 ГБ памяти — минимум, 8 ядер и 16 ГБ — рекомендуется (байесовская модель одного вида считается от 15 минут до 2 часов); диск от 20 ГБ.
- **Компьютер для проверки** (Windows, macOS, Linux): либо Docker Desktop, либо Python 3.11–3.13 и Node.js 20+.
- **Интернет** нужен для подложки карты (OpenStreetMap) и для выпуска HTTPS-сертификата при внешнем доступе. При установке — для загрузки пакетов Python и Node.js или образов Docker.
- **Браузер** пользователей: актуальные Chrome, Edge, Firefox или Safari.

### Способы

1. **Docker** — основной способ для сервера: «Установка с Docker».
2. **Без Docker** — для компьютера аналитика или проверки: «Установка без Docker».

После установки — «Первый запуск и загрузка данных».

## Установка с Docker

1. Установите Docker и Docker Compose (на macOS и Windows — Docker Desktop).
2. Скачайте приложение:

   ```bash
   git clone -b develop https://github.com/ALB040570/FISH_stock.git
   cd FISH_stock
   ```

3. Создайте файл настроек:

   ```bash
   cp .env.example .env
   python3 -c "import secrets;print(secrets.token_urlsafe(48))"   # выполните дважды
   ```

   Откройте `.env` в текстовом редакторе и задайте:

   | Переменная | Значение |
   |---|---|
   | `FISH_JWT_SECRET` | первая случайная строка (секрет подписи токенов входа) |
   | `FISH_SERVICE_TOKEN` | вторая случайная строка (токен вызовов между сервисами) |
   | `FISH_ADMIN_PASSWORD` | пароль первого администратора (логин `admin`) |
   | `FISH_WORKERS` | число одновременных расчётов (по умолчанию 2) |
   | `FISH_HTTP_PORT` | порт приложения (по умолчанию 8080) |

   Файл `.env` содержит секреты: не пересылайте его и не добавляйте в Git.

4. Соберите и запустите:

   ```bash
   docker compose up -d --build      # первая сборка — 10–20 минут
   docker compose ps                 # все сервисы должны быть в состоянии running / healthy
   ```

5. Откройте `http://<адрес сервера>:8080` и войдите: `admin` и пароль из `FISH_ADMIN_PASSWORD`.

Данные хранятся в томе Docker `fishdata` и сохраняются при перезапуске и обновлении.

Остановить: `docker compose down` (данные сохраняются). Журналы сервиса: `docker compose logs -f algo_admin`.

Дальше — «Первый запуск и загрузка данных».

## Установка без Docker

Подходит для Windows, macOS и Linux.

### Подготовка

- **Python 3.11, 3.12 или 3.13** (python.org). На macOS проверьте: `python3 --version`.
- **Node.js 20 или новее** (nodejs.org) — для сборки интерфейса.
- **Git** — для загрузки приложения (или скачайте архив с GitHub).
- На macOS желательно выполнить `xcode-select --install` (компилятор C++ ускоряет байесовскую модель в разы); на Linux — установить `g++`.

### Установка

```bash
git clone -b develop https://github.com/ALB040570/FISH_stock.git
cd FISH_stock
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cd frontend && npm ci && npm run build && cd ..
```

### Запуск

```bash
source .venv/bin/activate
FISH_ADMIN_PASSWORD='пароль-администратора' python deploy/run_local.py
```

На Windows: `set FISH_ADMIN_PASSWORD=пароль-администратора` и затем `python deploy\run_local.py` (или `run_local.bat`).

Когда появится строка `FishStock: http://127.0.0.1:8080`, откройте этот адрес. Окно терминала не закрывайте — в нём работает приложение; остановить — **Ctrl+C**.

- Данные — в папке `data` рядом с приложением (переменная `FISH_DATA_DIR` меняет место).
- Ключи `FISH_JWT_SECRET` и `FISH_SERVICE_TOKEN`, если не заданы, создаются автоматически и хранятся в `data/.secrets.json`.
- Пароль администратора задаётся только при первом запуске; дальше достаточно `python deploy/run_local.py`.
- Параметры: `--port 9000` (другой порт), `--workers 1` (число воркеров), `--host 0.0.0.0` (доступ с других компьютеров сети), `--port-base 9100` (другие порты сервисов, если 8001–8007 заняты).

Дальше — «Первый запуск и загрузка данных».

## Первый запуск и загрузка данных

### Вход администратора

Логин `admin`, пароль — из `FISH_ADMIN_PASSWORD`. Если пароль не был задан, он создан автоматически и записан в файл `users/INITIAL_ADMIN_PASSWORD.json` в каталоге данных (в Docker — в томе `fishdata`). После входа смените пароль.

### Что уже есть

- Справочники: 37 водоёмов (и Самаркандское водохранилище), 17 видов рыб, орудия лова (невод, сеть), 7 типов наборов данных.
- Каталог: 5 алгоритмов методики (эталонные версии) и профиль байесовской модели для Жайсана.
- Системные дашборды: «Мониторинг водоёма», «Сравнение водоёмов и лет».
- Справка (это руководство).

### Загрузка данных заказчика

В поставке — данные заказчика в шаблонах Excel (папка `samples/`): Жайсан, Балхаш, Капчагайское и Самаркандское водохранилища. Загрузить все водоёмы и создать расчёты:

```bash
python3 tools/seed_samples.py --password 'пароль-admin' --run stock
```

- `--url http://адрес:порт` — если приложение не на `http://127.0.0.1:8080`;
- `--water-body zhaysan` — только один водоём;
- `--run stock` — сразу запустить быстрый расчёт (этапы 1–3), `--run full` — полный, `--run none` — не запускать.

Повторный запуск загружает данные новой версией и не создаёт расчёты повторно.

Данные в прежнем формате (файлы `*_catch_YYYY.py`, `*_fish_prop.py`, `*_npc_assessment.py`) переносятся в шаблоны так:

```bash
python3 tools/legacy_to_excel.py --src <папка с файлами> --waterbody balkhash --out samples/balkhash
```

Ловы орудиями, отличными от «невод» и «сеть», и другие особенности переноса выводятся в конце работы команды.

### Пользователи

Создайте учётные записи сотрудников (**Управление → Пользователи** → **Новый пользователь**) — см. «Пользователи».

## Обновление приложения

Перед обновлением сделайте резервную копию — «Резервное копирование».

### С Docker

```bash
cd FISH_stock
git pull
docker compose up -d --build
```

### Без Docker

Остановите приложение (**Ctrl+C**), затем:

```bash
git pull
source .venv/bin/activate
pip install -r requirements-dev.txt
cd frontend && npm ci && npm run build && cd ..
python deploy/run_local.py
```

### На сервере, установленном скриптом

```bash
~/fishstock/deploy/server/update.sh --check   # что нового
~/fishstock/deploy/server/update.sh           # копия данных → загрузка → пересборка → проверка
```

Если сборка не удалась, продолжает работать прежняя версия; повторный запуск скрипта пробует снова.

### Что происходит с данными

- Данные, расчёты, запуски, пользователи, журнал сохраняются.
- Новые записи справочников из поставки (виды, водоёмы) добавляются; записи, которые вы изменили или удалили, не трогаются.
- Новые версии алгоритмов из поставки появляются в каталоге и включаются; прежние версии и запуски остаются.
- Системные шаблоны дашбордов обновляются, если их не меняли пользователи.
- Статьи справки обновляются, если их не правили в приложении; правленые статьи получают пометку ↻ («Правка справки»).

## Резервное копирование и восстановление

Все данные приложения — один каталог (том) данных. Копия этого каталога — полная резервная копия.

### С Docker

```bash
./deploy/backup.sh                                          # архив в ./backups, хранятся последние 30
./deploy/restore.sh backups/fishstock_20261024_030000.tar.gz
```

Ежедневная копия в 3:00 (cron): `0 3 * * * cd /opt/fishstock && ./deploy/backup.sh >> backups/backup.log 2>&1`

### Без Docker

```bash
python tools/backup.py create --data ./data --out ./backups
python tools/backup.py verify backups/<архив>.tar.gz
python tools/backup.py restore backups/<архив>.tar.gz --data ./data --force
```

Перед восстановлением остановите приложение.

### Проверка и хранение

- Архив содержит контрольные суммы всех файлов; `verify` проверяет целостность.
- При восстановлении прежнее состояние сохраняется: в Docker — в `/data/.before_restore` внутри тома, без Docker — в папку `data.before_restore_<дата_время>` рядом с каталогом данных.
- Храните копии **вне сервера** (другой диск, сетевое хранилище).
- Файл `.env` с секретами в архив не входит — храните его отдельно и надёжно.

## Доступ для коллег через интернет

Коллегам из других организаций создайте учётные записи с ролью **Наблюдатель** — они смогут только смотреть («Роли и права»).

### Постоянный доступ: сервер с доменным именем (HTTPS)

1. Заведите DNS-запись A для домена (например, `fish.example.kz`) на IP-адрес сервера; откройте порты 80 и 443.
2. В `.env` задайте `FISH_DOMAIN=fish.example.kz`.
3. Запустите:

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.public.yml up -d --build
   ```

   Сертификат HTTPS выпускается автоматически (Caddy, Let's Encrypt).

4. Отправьте коллегам адрес `https://fish.example.kz` и их логины.

### Сервер, где уже работают другие сайты

Если на сервере уже есть системный nginx и заняты порты 80, 443 или 8080, FishStock ставится рядом, ничего не меняя у соседей: приложение слушает только `127.0.0.1:8095`, а nginx получает один новый файл для отдельного адреса.

1. Установка (без sudo; пользователь должен быть в группе `docker`):

   ```bash
   git clone -b develop https://github.com/ALB040570/FISH_stock.git ~/fishstock
   ~/fishstock/deploy/server/install.sh
   ```

   Скрипт создаёт `.env` с секретами и паролем администратора (только на сервере), собирает и запускает контейнеры, загружает образцы данных и ставит ежедневную резервную копию (хранятся 7). В конце он показывает пароль администратора.

2. Адрес с HTTPS (нужен пароль sudo):

   ```bash
   ~/fishstock/deploy/server/nginx_site.sh
   ```

   Адрес по умолчанию — `fishstock.<IP через дефисы>.sslip.io`: он сам указывает на сервер, домен и DNS не нужны. Свой домен: `nginx_site.sh fish.example.kz`. Перед перезагрузкой nginx конфигурация проверяется; при ошибке файл FishStock убирается, и nginx не перезагружается. Сертификат выпускает Let's Encrypt (certbot).

3. Обновление — по команде: «Обновление приложения».

Порт и число воркеров меняются при первой установке: `FISH_PORT=8096 FISH_WORKERS=2 ~/fishstock/deploy/server/install.sh`.

### Временный доступ с компьютера

Если приложение запущено на вашем компьютере, временную ссылку даёт Cloudflare Tunnel:

```bash
brew install cloudflared            # macOS; для Windows и Linux — с сайта Cloudflare
cloudflared tunnel --url http://localhost:8080
```

Команда выдаст адрес вида `https://….trycloudflare.com`. Он работает, пока компьютер включён и окно команды открыто; при следующем запуске адрес будет другим.

> Давайте внешним пользователям только роль «Наблюдатель» и смените выданные пароли после работы.

## Частые проблемы

| Проблема | Что сделать |
|---|---|
| Страница не открывается | проверьте, что приложение запущено (`docker compose ps` или окно `run_local.py`), и адрес/порт |
| «Сервис временно недоступен» | один из сервисов не запущен или перезапускается; подождите минуту; в Docker — `docker compose logs <сервис>` |
| «Неверный логин или пароль» | проверьте раскладку клавиатуры; после 10 ошибок подряд учётная запись блокируется — к администратору |
| Забыт пароль администратора | другой администратор сбрасывает пароль; если администратор один — восстановите из резервной копии или обратитесь к разработчику |
| Port 8080 is already in use / адрес занят | запустите на другом порту: `FISH_HTTP_PORT=9000` в `.env` или `run_local.py --port 9000` |
| Карта без подложки | нет доступа в интернет к OpenStreetMap; контуры водоёмов всё равно видны |
| Расчёт долго «в очереди» | все воркеры заняты; увеличьте `FISH_WORKERS` (если хватает ядер и памяти) или дождитесь окончания |
| Байесовская модель считается очень долго | на сервере нет компилятора C++ (`g++`) — в Docker-образе он есть; без Docker установите `g++` / `xcode-select --install` |
| Ошибка «Нет профиля параметров байесовской модели» | создайте профиль водоёма («Управление → Параметры водоёмов») или запускайте этапы 1–3 |
| Ошибка шага расчёта | откройте запуск → шаг → **Журнал**; см. «Запуски и результаты» |
| Ошибки при загрузке Excel | «Ошибки при загрузке» |
| Docker: ошибка загрузки образов (403, timeout) | нет доступа к Docker Hub; проверьте сеть/прокси или используйте «установку без Docker» |

Если проблема не решается, сохраните текст ошибки (или снимок экрана) и журнал сервиса и передайте разработчику.
