# Требования FishStock v1

Источник: постановка задачи (18.10.2026), ответы на уточняющие вопросы и указания заказчика,
переданные Л. Мейрамбековой. **[Т]** — подтверждено, **[П]** — предложение, принятое при утверждении плана.

## Назначение
Веб-приложение для определения предельно допустимого улова (ПДУ) рыб в водоёмах Казахстана.
Пользователи — ихтиологи-аналитики и математики; администратор; наблюдатели (просмотр).

## Функциональные требования
1. **[Т]** Шесть отдельных микросервисов: пользователи; входные данные; администрирование алгоритмов;
   дашборды; моделирование данных (справочник); моделирование алгоритмов.
2. **[Т]** Главная страница — карта водоёмов, выбор водоёма на карте, переход к мониторингу.
3. **[Т]** Данные по всем водоёмам (заказчик передаст 19–20.10; сейчас есть только оз. Жайсан).
4. **[Т]** Администрирование пользователей, роли, блокировка; **журнал действий** — хранение 1 год, выгрузка в Excel.
5. **[Т]** Роли: администратор, ихтиолог, математик, **наблюдатель** (только просмотр; внешний доступ коллегам).
   Ограничений по водоёмам нет. Матрица — `docs/plan.md`, раздел 4.
6. **[Т]** Ихтиолог редактирует исходные данные и справочники, описывающие структуру данных.
   Каждая правка — новая версия, согласование не требуется.
7. **[Т]** Моделирование данных = конструктор справочников (сущности, поля, типы, единицы, обязательность).
8. **[Т]** Загрузка данных — Excel-шаблоны, генерируемые по справочникам; понятные ошибки проверки.
9. **[Т]** Моделирование алгоритмов: Python-код + манифест параметров, версии, проверка, публикация.
10. **[Т]** Администрирование моделей расчёта, просмотр их версий.
11. **[Т]** «Расчёт» — сущность: набор исходных данных + алгоритм(ы) + формат результатов + режим / последовательность запуска.
12. **[Т]** Параметры алгоритма: неизменяемые (в версии алгоритма); зависящие от водоёма; параметры запуска.
13. **[Т]** Наглядные дашборды мониторинга: исходные данные, запасы, коэффициенты уловистости; ПДУ — наглядно и прозрачно.
14. **[Т]** Дашборды: готовые шаблоны и конструктор.
15. **[Т]** Длительные расчёты — очередь и N воркеров, не блокируют интерфейс.
16. **[Т]** Экспорт: Excel, NetCDF, отчёт Word/PDF (структуру отчёта предлагает разработчик).
17. **[Т]** Интерфейс на русском и казахском (казахский перевод готовит разработчик, проверяет заказчик).
18. **[Т]** Вход по логину и паролю.
19. **[Т]** Мониторинг показывает «основной запуск» водоёма; если не отмечен — последний успешный (с пометкой).
20. **[Т]** Водоём: точка обязательна, контур — по желанию; крупные водоёмы загружаются заранее из OpenStreetMap.

## Нефункциональные
- **[Т]** Vue (фронтенд), Python (расчёты), файловое хранение в v1, переход на PostgreSQL предусмотрен.
- **[Т]** 10–50 пользователей. Сервер с доступом в интернет (подложка карты OSM). Место размещения не определено → Docker Compose.
- **[Т]** Формулы и коэффициенты не придумываются; эталон для сверки — результаты и тесты `fish_stock_forecast`
  (детерминированные этапы — 1e-6, байесовская модель — медианы ±5 %, R̂ < 1,05).
- **[Т]** История расчётов не перезаписывается; пропуски не заменяются нулями.
- **[Т]** Срок сдачи — 25.10.2026, полный объём.
