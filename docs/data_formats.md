# Форматы данных и хранение

## 1. Типы наборов данных (по данным оз. Жайсан)

Шаблон Excel для любого типа скачивается в разделе «Расчёт → Исходные данные» (или `GET /api/data-admin/templates/<тип>.xlsx`).
Лист **«Данные»** — заголовки (оранжевые — обязательные, зелёные — столбцы видов), выпадающие списки для перечислений
и ссылок; лист **«Описание»** — столбцы, типы, единицы, допустимые значения.

| Код | Набор | Ключ | Столбцы | Столбцы видов |
|---|---|---|---|---|
| `catches` | Уловы по ловам | — (строка = лов) | год, дата (ДД.ММ.ГГГГ), место, орудие (невод/сеть), описание орудия, размер орудия, м, обловленная площадь, га, тип лова | улов, шт |
| `age_samples` | Возрастные пробы | год + возраст | год, возраст j | число рыб в пробе, шт |
| `mean_weights` | Средний вес по возрастам | год + возраст | год, возраст j | средний вес, г |
| `species_props` | Биологические параметры видов | вид | вид, m0, m1, m2, скорость блуждания `v_cr` (м/с; до 25.10.2026 — «Крейсерская скорость», прежний заголовок принимается), k сети, k невода, хищник, плодовитость мин/макс, плотность мальков (шт/м²) | — |
| `yearly_conditions` | Условия по годам | год | год, площадь водоёма (км²), длина сети (м), время стоянки (ч) | — |
| `npc_stock` | Оценка запаса НПЦ | год | год | запас, тыс. шт |
| `npc_pdu` | ПДУ НПЦ | год | год | ПДУ, т |

Возраст j — как в исходных данных: группа «от j−1 до j лет» (j = 2 — двухлетки, в интерфейсе «1–2»).

**Пропуски.** Пустая ячейка — пропуск («вид в этом лове не учитывался»), хранится как `null` и в расчётах — как NaN;
ноль — учтённый нулевой улов. Пропуски никогда не заменяются нулями.

**Проверки при загрузке:** структура (известные и обязательные столбцы, повторы), типы (целое, число, дата, да/нет),
пределы (min/max), значения перечислений и ссылок на справочники, повтор ключа, правила (m0 ≤ m1, m2 ≤ m1,
плодовитость мин ≤ макс), предупреждение о несовпадении года даты и года лова. Ошибки — с номером строки Excel.

**Режимы загрузки:** `merge` — заменить годы (или ключи), которые есть в файле, остальные сохранить;
`replace` — заменить набор целиком. Любая загрузка или правка создаёт новую версию; исходный файл сохраняется.

Новые типы наборов и справочники создаются в конструкторе («Конструктор → Структура данных»). Системные поля и столбцы (используются
алгоритмами) нельзя удалить или сменить им тип.

## 2. Хранение (v1 — файлы)

Каталог данных (`/data` в Docker, `./data` без Docker), по каталогу на сервис:

```
users/users/<id>/meta.json                 пользователь (пароль — хеш argon2)
users/audit/YYYY-MM-DD.jsonl               журнал действий (365 дней)
data_model/entities/<код>/meta.json + versions/<n>/schema.json
data_model/records/<справочник>/<id>/meta.json + versions/<n>/record.json
data_model/dataset_types/<код>/meta.json + versions/<n>/schema.json
data_admin/datasets/<id>/meta.json + versions/<n>/{data.json, source.xlsx, version.json}
algo_model/algorithms/<код>/meta.json; drafts/<id>/versions/<n>/package.zip; tests/<id>/...
algo_admin/catalog/<код>/versions/<n>/{package.zip, manifest.json, version.json}
algo_admin/profiles/<алгоритм>__<водоём>/versions/<n>/values.json
algo_admin/calculations/<id>/versions/<n>/definition.json
algo_admin/runs/<id>/meta.json, inputs/{tables.json, dictionaries.json}, steps/<NN>_<шаг>/{context.json, package/, out/, log.txt, status.json}
algo_admin/main_runs.json                  основной запуск по водоёмам
dashboards/dashboards/<id>/meta.json + versions/<n>/dashboard.json
```

- Идентификаторы — ULID (сортируются по времени создания), переходят в БД без изменений.
- Запись: временный файл в том же каталоге → `os.replace` (атомарно), под файловой блокировкой объекта.
- Версии только добавляются; запуск хранит **снимок исходных данных** (`inputs/tables.json`), версии наборов,
  контрольные суммы пакетов алгоритмов, итоговые параметры, результаты, журнал и ошибки — история не перезаписывается.
- `data.json` набора: `{"columns": [...], "species": [коды видов], "rows": [{...}]}`.

### Результат шага (`out/result.json`)

```json
{"tables": {"<код>": {"title": "...", "columns": [{"code", "title", "unit", "type"}], "rows": [{...}]}},
 "files": [{"name", "title", "format"}], "payload": {...}, "metrics": {"<код>": {"value", "title", "unit"}},
 "notes": ["..."], "seconds": 1.2}
```

Файлы NetCDF этапов 1–3 — с теми же именами и переменными, что `data_stock` исходного проекта
(`zhaysan_catch_net_3d.nc`, `zhaysan_stock_seine_with_ages_3d.nc`, …); байесовская модель — `zhaysan_bayes_<вид>.npz/.nc`.

## 3. Переход на PostgreSQL (следующий этап)

Сервисы работают с хранилищем через `fishcommon.storage.Collection` (интерфейс `Repository`: create/get/list/update/delete
и версии). Для PostgreSQL добавляется реализация того же интерфейса: таблица объектов (`id`, `collection`, `meta jsonb`)
и таблица версий (`object_id`, `n`, `info jsonb`, содержимое — `jsonb` или `bytea`/объектное хранилище для файлов);
журнал — таблица с индексом по времени; очередь запусков — `SELECT … FOR UPDATE SKIP LOCKED`. API сервисов не меняется.
Перенос — скриптом, читающим каталог данных и записывающим объекты с теми же ULID.
