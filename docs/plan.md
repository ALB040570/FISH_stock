# План FishStock v1 (утверждён 18.10.2026)

Утверждён с уточнениями (редактор водоёма, связь карты и мониторинга, дашборды) и добавлением
роли «Наблюдатель» для внешнего просмотра. Повторного утверждения в следующих сессиях не требует.

## 1. Основа
Расчётное ядро `legacy/fish_stock_forecast/core` (этапы 1–5) сохраняется **без изменения формул**.
Меняются: интерфейс (Jinja → Vue), архитектура (монолит → 6 сервисов), источник данных
(`.py` → наборы данных по Excel-шаблонам), привязка к Жайсану → параметры водоёма.

## 2. Понятия
- **Справочник** (data-model): сущности и поля; типы наборов данных (схемы таблиц).
- **Набор данных** (data-admin): таблица заданного типа для водоёма и периода, неизменяемые версии.
- **Алгоритм** (algo-model → algo-admin): версия Python-пакета с манифестом. Параметры:
  `fixed` (неизменяемые, в версии), `waterbody` (профиль «водоём × вид», версии), `run` (форма запуска).
- **Расчёт** (algo-admin): наборы данных + цепочка версий алгоритмов + формат результатов + режим запуска.
- **Запуск**: неизменяемая запись — версии данных, алгоритмов, профилей, параметры, результаты, журнал, ошибки.
- **Основной запуск** водоёма — проверенный запуск, который показывает мониторинг.

## 5. Экраны

### Кабинеты (утверждено 23.10.2026, заменяет единое меню от 20.10)
По предложению руководителя (Габбасов М.): у разных пользователей — отдельные интерфейсы. Один код фронта,
несколько отдельно собираемых приложений (многостраничная сборка Vite), единый вход, общий домен.

| Кабинет | Адрес | Что в нём | Кто входит |
|---|---|---|---|
| Мониторинг | `/monitoring/` | карта, мониторинг водоёма, дашборды | все роли (наблюдатель и оператор — чтение) |
| Ввод данных | `/input/` | наборы данных: загрузка Excel, правка, версии, сравнение | админ, ихтиолог, математик, оператор |
| Расчёты | `/calc/` | расчёты, запуски, основной запуск, параметры водоёмов | админ, ихтиолог, математик |
| Конструктор | `/design/` | справочники, алгоритмы, порядок расчёта, дашборды, правила замечаний | админ, ихтиолог, математик |
| Администрирование | `/admin/` | пользователи, журнал действий, каталог алгоритмов | админ, математик |

- Вход — `/login`. Админ, математик, ихтиолог попадают на стартовую страницу **«Поток»** (`/`, вариант Г, утверждён
  23.10): кабинеты пути данных Ввод данных → Расчёты → Мониторинг, между ними «трубы» с водоёмами, ждущими
  следующего этапа (ждут расчёта → идёт расчёт → ждут отметки основного → готов); ниже — Конструктор и
  Администрирование. Состояние водоёма — те же факты, что красят карту; пустые трубы — «поток свободен»; в трубе до
  3 водоёмов и «ещё N»; «Продолжить» (последний экран, в браузере); клавиши 1–5. Выбор сделан по ТРИЗ (противоречие
  «много и мало информации», разделение по условию, использование стрелок как ресурса).
- Наблюдатель — сразу «Мониторинг», оператор ввода данных — сразу «Ввод данных» (стартовой страницы нет).
  Переключатель кабинетов — в шапке, если кабинетов больше одного.
- **Роль «Оператор ввода данных»** (23.10): загрузка, проверка, правка наборов данных, версии; Мониторинг — чтение;
  расчёты, справочники, алгоритмы, дашборды, пользователи — нет.
- Наблюдателю на карте и в «Потоке» не показываются внутренние состояния («данные новее расчёта», «идёт расчёт»).
- Справка — в каждом кабинете (`/<кабинет>/help`). Переходы между кабинетами — обычные ссылки (страница перезагружается).
- Старые адреса (`/data/…`, `/runs/…`, `/monitoring/<водоём>` и др.) перенаправляются на новые.
- Права API не меняются; ссылки в кабинет, куда роль не входит, показываются текстом.
- Мониторинг не меняется (краткий «Обзор» не делаем — решение заказчика 23.10).
- Фронт «Ввод данных» для рыбаков-любителей — после кабинетов, если останется время до 25.10, иначе после сдачи.

### Редактор водоёма
Справочники → Водоёмы: список + карта. Поля: название ru/kk, тип, область, бассейн, площадь, точка, контур.
Точка — клик по карте (обязательна). Контур — по желанию: обвести, загрузить GeoJSON/KML или выбрать
объект OSM. Крупные водоёмы загружены заранее. Сохранение — новая версия, запись в журнал.

### Карта → мониторинг
Цвет водоёма: серый — нет данных, синий — есть данные, зелёный — есть расчёт, оранжевый — данные новее расчёта.
Клик — панель (виды, последний расчёт, ПДУ) и кнопки «Мониторинг», «Данные», «Запустить расчёт».

### Дашборды и мониторинг
Мониторинг — системный шаблон дашборда, параметризованный водоёмом. Шаблон ведут админ/математик;
«Сделать копию» — личный/общий дашборд в конструкторе.

## 7. Хранение
`/data/<сервис>/<коллекция>/<ULID>/meta.json` + `versions/<n>/...`; запись через временный файл + `os.replace`
под блокировкой; версии только добавляются; пропуски — NaN/пусто. Слой `Repository` → позже PostgreSQL.
Бэкап/восстановление — `deploy/backup.sh`, `deploy/restore.sh`.
