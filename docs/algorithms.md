# Алгоритмы: как устроены и как добавить новый

## Эталонные алгоритмы (версия 2.0.0, эталон 22.10.2026)

Перенесены из `legacy/fish_stock_forecast/core` (эталон 22.10.2026, формулы — статья в редакции 21.10.2026) без
изменения формул; общий код — `algorithms/fishcore`. Прежние эталонные версии 1.0.x удаляются из каталога при запуске
сервиса (решение № 51); запуски по ним остаются для просмотра. `bayes_cohort` и `bayes_checks` — 2.0.1 (решение № 60):
расчёт видов вне эталона (коды видов для файлов — из справочника), для видов Жайсана результаты те же; 2.0.0 остаётся
в каталоге (эталонные версии той же основной версии не удаляются).
2.0.2 (решение № 63): виды модели, а в проверках — каждая проверка вида и каждый вариант учёта пустых ловов считаются
одновременно, каждый в своём процессе со своими seed и цепями (`fishcore/bayes/parallel.py`); лимит ядер —
`FISH_CALC_CORES` (по умолчанию 32, не больше ядер машины), процессов — лимит ÷ число цепей; при одном процессе — по
очереди, как раньше. Числа те же, что при расчёте по очереди (`algorithms/tests/test_parallel.py`, `FISH_SLOW_TESTS=1`).

| Код | Шаг | Методика | Предыдущие шаги |
|---|---|---|---|
| `seine_catchability` | Уловистость невода | сигмоида, МНК по годовым уловам, ограничения (25)–(26); сглаживание пробы — одна условная рыба на пробу, малые пробы — с соседними годами | — |
| `stock_by_catch` | Уловистость сети и запас по уловам | парабола (22)–(24) с краями c̄/3 и 2c̄/3, модель баланса 12 колец с подшагами в круге 0, (27), (28) с √n сетей одной ячеи, объединение сети и невода | seine_catchability |
| `pdu_by_age` | ПДУ НПЦ по возрастам | раздел 2.4: распределение квоты по биомассе с нагрузкой j/m1, ≤ 75 % за итерацию | stock_by_catch |
| `bayes_cohort` | Байесовская когортная модель | (33)–(35), правдоподобие (36)–(38) (дельта-логнормальное; плотва — с константой, карась — гамма), PyMC/NUTS, диагностика R̂/ESS/E-BFMI | stock_by_catch, pdu_by_age |
| `forecast_pdu` | Прогноз и ПДУ | продолжение (33)–(34) по 500 выборкам; F = k·M (Баранов), фиксированный ПДУ, без промысла | bayes_cohort |
| `bayes_checks` | Проверки байесовской модели | п. 2.7 и 3.4: ретроспективный прогноз, априорные × 2, учёт пустых ловов, синтетические данные, чувствительность балансового метода | bayes_cohort |

Номера формул — для документации разработчика; в интерфейсе и справке их нет (решение № 46).

Изменения относительно `fish_stock_forecast` (формулы не затронуты): чтение данных из наборов (`fishcore/bundle.py`,
ветка в `data_source.py`; тип лова — код справочника, число сетей одной ячеи по нему), аргумент `data_dir` у `compute_pdu`,
настройки байесовской модели из профиля водоёма (`bayes/config.set_runtime`), результаты в каталог шага, графики
диагностики (PNG) не строятся; представления для интерфейса — `fishcore/views.py`; режим «сверка со старым скриптом» не перенесён.

## Пакет алгоритма

```
manifest.json      описание: код, версия, параметры, требуемые данные и шаги, результаты
algorithm.py       точка входа: def run(ctx)
<модули>.py        любой дополнительный код (например, вложенная копия fishcore)
```

`manifest.json`:

```json
{"code": "my_method", "version": "1.0.0", "title_ru": "...", "title_kk": "...", "description": "...",
 "entrypoint": "algorithm:run", "runtime": {"python": ">=3.11", "timeout_minutes": 30},
 "requires": {"datasets": ["catches", "npc_pdu"], "steps": ["stock_by_catch"]},
 "parameters": [
   {"code": "PDU_CAP", "title_ru": "...", "type": "number", "default": 0.75, "category": "fixed", "min": 0, "max": 1},
   {"code": "species_profiles", "title_ru": "...", "type": "profile", "category": "waterbody"},
   {"code": "horizon", "title_ru": "...", "type": "integer", "default": 5, "category": "run", "min": 1, "max": 10}],
 "outputs": [{"code": "result", "title_ru": "...", "format": "table"}]}
```

**Категории параметров:** `fixed` — неизменяемые (меняются только новой версией алгоритма; если имя совпадает с
настройкой `fishcore.config`, значение применяется до загрузки кода); `waterbody` — из профиля водоёма
(«Управление → Параметры водоёмов», версии); `run` — задаются в расчёте или при запуске.
**Типы:** integer, number, enum, boolean, string, species_list, year_map, species_map, species_year_map, profile.

## Контекст `ctx`

| | |
|---|---|
| `ctx.tables` | наборы данных водоёма: `{тип: {"columns", "species", "rows"}}` (снимок на момент запуска) |
| `ctx.params` | итоговые параметры шага |
| `ctx.water_body`, `ctx.species_names`, `ctx.gear_kinds` | водоём, коды видов → названия, орудия → seine/net |
| `ctx.load_state("<шаг>")` | объект, сохранённый предыдущим шагом цепочки (`ctx.save_state(obj)`) |
| `ctx.input_dir("<шаг>")` | каталог результатов предыдущего шага |
| `ctx.add_table(code, title, columns, rows)`, `ctx.add_frame(code, title, df)` | таблицы результата (дашборды, отчёты) |
| `ctx.add_file(name, title)` → путь | файл результата (Excel, NetCDF, …) |
| `ctx.set_payload(dict)`, `ctx.metric(...)`, `ctx.note(...)` | данные для особых представлений, показатели, примечания |
| `ctx.log(...)`, `ctx.progress(доля, **info)` | журнал и ход выполнения (проверяет отмену) |
| `raise fishrunner.UserError("...")` | понятная пользователю ошибка без трассировки |

## Порядок работы математика

1. «Конструктор → Алгоритмы» → «Новый алгоритм» (шаблон) или «Новый черновик от версии» опубликованного алгоритма.
2. Правка файлов в редакторе или загрузка zip; каждое сохранение — ревизия черновика.
3. «Проверить» — манифест, категории и типы параметров, синтаксис Python, точка входа, номер версии.
4. «Тестовый прогон» на данных выбранного водоёма: предшествующие шаги выполняются опубликованными версиями
   (байесовская модель как предшественник — короткой выборкой); можно сверить результаты с опубликованной версией
   (наибольшее относительное отличие по каждой таблице).
5. «Опубликовать» — только после успешного теста текущей ревизии. Версия появляется в каталоге (включена);
   администратор или математик может её отключить. Расчёты используют последнюю включённую версию либо закреплённую.
