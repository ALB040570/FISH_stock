# Алгоритмы, параметры алгоритмов, расчёты (решение № 70)

Статус: утверждено заказчиком 24.10.2026 (замечания Марса Габбасова), выполнено 25.10.2026.
Формулы и числа не менялись — изменилось только то, как алгоритмы вызываются и хранятся.

## 1. Сущности
| Сущность | Что это | Где хранится |
|---|---|---|
| **Алгоритм** (каталог) | абстрактный метод: входы (наборы данных и/или результаты других алгоритмов), результаты, параметры со значениями по умолчанию; реализация — отдельный пакет `algorithms/packages/<код>` (версия 3.0.0) | `algorithms/catalog.json` (a–k), версии кода — `algo_admin/catalog/<код>/versions/<n>`; включают и отключают версии администратор и математик |
| **Параметры алгоритма** | набор значений всех параметров одного алгоритма (категория `param`), включая прежние «неизменяемые» коэффициенты; общий, к водоёму не привязан | `algo_admin/param_sets/<id>/versions/<n>/values.json`; «По умолчанию (эталон)» — `default_<код>`, не меняется |
| **Расчёт** | алгоритм + версия кода (пусто — последняя включённая) + водоём + период + входы + набор параметров и версия + виды модели/прогноза (категория `calc`). Один результат, новый запуск затирает прежний | `algo_admin/calcs/<id>/` — `meta.json`, `result/`, `work/`, `journal.json`, `last_log.txt` |
| **Журнал расчёта** | запись о каждом выполнении: кто, когда, версия и контрольная сумма кода, наборы данных и версии, набор параметров и версия, период и годы, расчёты-входы (id расчёта и id результата), длительность, ошибка | `journal.json`, только добавляется |
| **Основной расчёт** | один на алгоритм × водоём; его показывает мониторинг и берут входом другие расчёты; остальные — альтернативные. Первый готовый результат становится основным автоматически | `algo_admin/mains.json` `{водоём: {алгоритм: {calc_id}}}` |

Отдельной сущности «запуск» нет. Состояния расчёта: не считался, в очереди, идёт (ход, отмена), готов, ошибка;
отметка «устарел» вычисляется при каждом запросе.

## 2. Входы и устаревание
- **Наборы данных** — всегда последняя версия набора водоёма.
- **Результаты алгоритмов** — по умолчанию основной расчёт нужного алгоритма водоёма; можно указать любой
  альтернативный (`inputs: {код: calc_id}`). Если основного ещё нет, но расчёт входа стоит в очереди или идёт —
  расчёт можно поставить в очередь, воркер возьмёт его после входа.
- **Устарел**, если с момента последнего результата: появилась новая версия использованного набора данных;
  расчёт-вход пересчитан (другой id результата); для входа «основной» сменился основной расчёт; вышла новая
  версия кода, которой считался расчёт без закреплённой версии; сам расчёт-вход устарел (отметка передаётся
  по цепочке). Пересчёт — вручную (по одному или
  «Пересчитать устаревшие» — в порядке зависимостей). Последовательности одной кнопкой нет.
- **Период** — у любого алгоритма; если период входа не покрывает период расчёта — предупреждение.

## 3. Каталог a–k
Всегда с учётом возрастов (вариант «без учёта возрастов» убран). Способ годового запаса «по запасам / по улову» —
параметр `STOCK_METHOD` у e и f (g наследует). Тонны = запас × средний вес по возрастам (веса — как в ПДУ, пропуск —
вес младшего возраста): все возрасты и промысловые (возраст ≥ m0).

| | Код пакета | Алгоритм | Входы-результаты | Наборы данных |
|---|---|---|---|---|
| a | net_catchability | Уловистость сети по возрастам и годам | — | уловы, возрастные пробы, параметры видов, условия, средние веса |
| b | seine_catchability | Уловистость невода по возрастам и годам | — | те же |
| c | seine_likelihood | Правдоподобие методом площадей (невод) | b | уловы, условия, средние веса |
| d | net_likelihood | Правдоподобие балансовым методом (сеть) | a | уловы, параметры видов, условия, средние веса |
| e | seine_stock | Ежегодный запас методом площадей (шт и т) | c | средние веса |
| f | net_stock | Ежегодный запас балансовым методом (шт и т) | d | средние веса |
| g | combined_stock | Ежегодный запас, усреднённый по неводу и сети (шт и т) | e, f | средние веса, оценка запаса НПЦ (необязательна) |
| h | pdu_by_age | ПДУ в экземплярах | g | ПДУ НПЦ, средние веса, параметры видов |
| i | bayes_cohort | Запас по математической модели | c, d, g, h | параметры видов, условия |
| j | forecast_pdu | Прогноз запаса и оценка ПДУ по модели | i | параметры видов, условия, ПДУ НПЦ |
| k | removal_pdu | Оценка ПДУ на основе коэффициента изъятия | g | — «Планируется», без реализации |

- Виды модели (i, j) выбираются в расчёте; профили видов (априорные распределения, варианты формул) — в наборе
  параметров алгоритма i.
- «Проверки байесовской модели» (bayes_checks) — пакет сохранён, в каталог не входит (решение № 65).
- Проверка: при параметрах по умолчанию a–h на Жайсане совпадают с прежним расчётом до 1e-12 и с эталоном
  22.10 до 1e-6 (`algorithms/tests/test_pipeline.py`); i — тот же код модели и seed.

## 4. API (algo-admin)
- Каталог: `GET /catalog`, `/catalog/{код}`, `POST /catalog/{код}/versions/{n}/enable|disable`.
- Параметры: `GET|POST /param-sets`, `GET|PUT|DELETE /param-sets/{id}` (`?version=`), `/param-sets/species-defaults/{вид}`.
- Расчёты: `GET|POST /calcs`, `GET|PUT|DELETE /calcs/{id}`, `POST /calcs/{id}/check|run|cancel|main`,
  `POST /calcs/recalc-stale`, `GET /calcs/{id}/result|log|journal|files/{имя}|export.zip`, `GET /queue`.
- Водоёмы: `/water-bodies/status`, `/water-bodies/{wb}/mains`, `/water-bodies/{wb}/main-result?algorithm=`,
  `/water-bodies/{wb}/report.docx|pdf`.

Права: создавать и запускать расчёты, создавать наборы параметров — администратор, ихтиолог, математик; версии кода —
администратор и математик; «Презентация» — список и состояния без результатов (решение № 62).

## 5. Интерфейс — кабинет «Расчёты запасов рыб» (`/calc/`)
- **Расчёты** (`/calc/calculations`) — список с фильтрами (водоём, алгоритм, только устаревшие), «Новый расчёт»,
  «Запустить / Пересчитать», «★ Сделать основным», «Пересчитать устаревшие»; карточка расчёта — входы, параметры,
  результат (таблицы, графики, файлы, zip), журнал.
- **Каталог алгоритмов** (`/calc/catalog`) — карточки a–k, версии кода, «Запустить с параметрами по умолчанию».
- **Параметры алгоритмов** (`/calc/params`) — наборы по алгоритмам, версии, сравнение, «Создать на основе…».
- Старые адреса (`/runs`, `/profiles`, `/admin/catalog`, `/design/catalog`, `/design/calculations`) перенаправляются.
- Мониторинг и «Поток» собираются из основных расчётов a–j, с отметкой «устарел».

## 6. Перенос данных на сервере
При первом запуске новой версии (`migrations.json` → `catalog_v3`): прежние запуски (`runs/`), цепочки
(`calculations/`), `main_runs.json`, записи каталога stock_by_catch и bayes_checks удаляются (решение заказчика);
профили байесовской модели водоёмов переносятся в наборы параметров алгоритма i с сохранением правок; создаются
наборы «По умолчанию» a–j. Наборы данных, справочники, пользователи, комментарии, дашборды не трогаются.
После обновления расчёты создаются заново (Каталог → «Запустить» или `tools/seed_samples.py --run stock`).
