Прочитайте перед любой работой с репозиторием. Общайтесь с заказчиком на русском.

## Главное: рабочая установка — сервер, а не компьютер заказчика (с 23.10.2026)

Приложением пользуются на сервере: **https://fishstock.89-218-32-75.sslip.io**. Там работают заказчик и
коллеги-ихтиологи и математики; они тестируют и пишут комментарии к виджетам. Запуск на Mac заказчика
(`run_local.sh`, папка `~/Documents/2026/Рыба/FISH_stock`) — только для разработки и проверки, его данные не
совпадают с серверными.

## Как изменения попадают на сервер

1. Сессия делает commit и push в **develop**.
2. Сервер **не обновляется сам** — только по команде заказчика. После push скажите заказчику, что выполнить:
   `~/fishstock/deploy/server/update.sh` (резервная копия → `git pull` → пересборка → перезапуск шлюза → проверка
   всех 7 сервисов; при сбое сборки работает прежняя версия). Предупредите, если пересборка будет долгой
   (изменились зависимости Python — образы сервисов алгоритмов собираются до 40 минут) — тогда в фоне:
   `cd ~/fishstock && nohup ./deploy/server/update.sh > update.log 2>&1 &` и `tail -f update.log`.
   Обновление пересоздаёт контейнер воркера и **обрывает идущий расчёт**: `update.sh` (с 24.10) показывает идущие
   запуски и без подтверждения/`--force` не обновляет; оборванный запуск помечается «прерван». Перед обновлением
   спросите заказчика, не идёт ли долгий расчёт (байес), или предложите `update.sh --check`.
3. **develop = то, что получат пользователи.** В develop — только законченное и проверенное (`pytest`, `npm test`,
   e2e). Незаконченное — в отдельную ветку.

## Что учитывать в работе

- **Код должен работать в Docker**, а не только через `run_local.py`. В образе сервис лежит в `/srv/app`,
  алгоритмы — `/srv/algorithms`, `fishcommon` установлен пакетом; остального репозитория в образе нет.
  Не вычисляйте пути через `Path(__file__).parents[N]` к корню репозитория; новые файлы, нужные сервису, должны
  копироваться в `deploy/service.Dockerfile`; новые зависимости — в `services/<сервис>/requirements.txt`
  (не только в `requirements-dev.txt`). Не добавляйте в Git `build/`, `*.egg-info` (см. `.dockerignore`).
  Сборку Docker в среде Claude проверить нельзя (Docker Hub закрыт) — проверяйте раскладку образа без Docker
  (скопировать `app/` в каталог глубины `/srv/app` и импортировать) и предупреждайте заказчика, что окончательная
  проверка — на сервере.
- **На сервере живые данные.** Изменения форматов хранения, справочников, схем — только с переносом существующих
  данных при запуске (как `_migrate_regions` в data_model), без требования очистить том. Комментарии и
  учётные записи коллег не должны теряться.
- **Сервер общий.** Не предлагайте менять чужие сайты nginx, системные настройки, порты соседей. Тяжёлые расчёты
  (байесовская модель) запускать только с согласия заказчика.
  Байес и проверки считают виды одновременно (решение № 64): лимит ядер одного расчёта — `FISH_CALC_CORES` в
  `~/fishstock/.env` (по умолчанию 32); менять — правкой `.env` и `update.sh`.
- **Доступ.** Из среды Claude к серверу по SSH подключиться нельзя: команды выполняет заказчик в Терминале
  (на сервере приглашение `lazzat@admin:~$`) и присылает вывод. Сайт можно проверять через Claude in Chrome;
  входит в приложение только сам заказчик (пароли не вводить).
- **Диагностика на сервере:** `cd ~/fishstock && docker compose ps -a`; `docker compose logs --tail 50 <сервис>`;
  `curl -s http://127.0.0.1:8095/api/<сервис>/health`; если сервис отвечает, а через шлюз нет —
  `docker compose restart web`.
